# 中断恢复、文件检查点与 Worktree

nanoCursor 默认在原目录编辑。运行记录用于核查中断的操作；文件检查点用于撤销受控的文件编辑；Worktree 是可选的独立代码目录。这三项能力各自有边界。

## 中断后先核查，不自动重跑

终端或进程意外退出后，下次启动会核查持久执行记录。已经保存的工具结果可补回对应会话；有执行意图、没有可靠结果的操作显示为结果未知，并阻止同一 Git 项目的后续自主执行。新建会话、切换 Worktree 或回退对话不能消除这些记录。

程序不会静默重发旧 Bash/MCP 调用，也不会启动另一个 Agent 查询数据库、补偿操作或猜测结果。一个失败、取消或超时的调用仍可能已经产生部分影响。恢复出来的返回值带原观察时间，只表示当时的结果，不能用作当前库存、数据库或进程状态。

在交互界面检查：

```text
/recover
/recover acknowledge <operation_id> 已检查相关文件和外部系统，接受仍未知的影响
```

也可在目标项目目录中直接检查，无需配置或调用模型：

```bash
nanocursor recover --list
nanocursor recover --list --json
nanocursor recover --cwd /path/to/project --list
nanocursor recover --ack <operation_id> --note '已人工核查，接受仍未知的影响'
```

`acknowledge` / `--ack` 是用户的处置决定，不会把原始未知记录改写成成功，也不会重试原操作。它允许开始新一轮任务；新操作仍走正常权限检查。先自行处理可能仍在写文件的旧进程，程序不会根据历史 PID 自动杀进程。

同一 checkout 只允许一个 nanoCursor 执行拥有者；不同 Worktree 可分别运行。检查正在运行的会话时使用它的 `/recover`，或通过另一个终端的 `recover --list` 只读查看；只读查看不会把活动操作改判为崩溃，也不能替活动拥有者确认结果。另一进程不能抢占当前工作区。文件锁只协调 nanoCursor，不会锁住外部编辑器。

主交互 CLI 和 `-p` 共用执行保护。文字仍流式显示，但工具要等完整模型回复及其工具批次保存后才启动。前后 Hook、后台任务、独立 Skill、Team 成员和 MCP 启动/调用分别保留执行记录；父任务结束不代表子任务已经结束。重启恢复记录，不恢复 Python 协程或自动续跑后台任务。

非交互运行的特殊终止状态：

| 退出码 | `stop_reason` | 含义 |
| --- | --- | --- |
| 3 | `recovery_required` | 有待人工核查的未知操作或未完成文件恢复 |
| 4 | `recovery_storage_error` | 无法可靠保存或读取恢复状态，或无法取得执行拥有权 |

`--output-format stream-json` 的最终 `result` 同时给出 `exit_code` 和 `stop_reason`。磁盘满、日志损坏或提交失败时会停止，不降级为无记录执行。

## 文件检查点：先预览，再确认

每轮用户任务在受控文件修改之前建立检查点。文件采用首次编辑时的惰性备份，保存实际内容，包括原有未提交修改。检查点能跨进程保留，但不是用户发消息那一刻整个项目的快照。

```text
/rewind
/rewind 1 1
```

第二条命令只预览第一个检查点，显示完整稳定 ID、工作区、文件增删改、差异、冲突和未覆盖范围。选项含义：

| 选项 | 行为 |
| --- | --- |
| 1 | 恢复记录的文件编辑和检查点对话 |
| 2 | 只恢复对话，追加“文件和外部效果未撤销”的提醒 |
| 3 | 只恢复文件，在当前对话追加准确的恢复说明 |

确认执行时，复制预览里的完整 ID：

```text
/rewind <完整_checkpoint_id> 1 apply
```

数字或缩写可用于查看；实际执行必须使用完整 ID。执行前会重新核查文件、备份、工作区、未知操作和任务状态。请先停止后台任务和仍登记为活动的 MCP 服务，并暂停外部编辑器写入。恢复对话后，模型审批退回人工确认，直到新建会话，避免沿用旧分支的授权。

覆盖受控的 `WriteFile` / `EditFile` 普通文件编辑，包括撤销新建文件、恢复旧内容及普通权限位；接入相同执行服务的子 Agent 也按所属工作区记录。以下内容不属于文件回退保证：

- Bash、MCP、Git 操作、外部编辑器及远端系统的改动；
- 经审批的项目外文件编辑；工具结果和预览会明确标注；
- 软链接、经过软链接的父路径、硬链接、目录和特殊文件；内置文件编辑会拒绝这些目标，macOS 经校验的系统 `/tmp`、`/var` 路径别名除外；
- 空目录清理、ACL、扩展属性和扩展权限。

工作区内应受保护的文件备份失败会阻止写入。Git 元数据和恢复存储不能作为普通检查点编辑目标。单个文件或预期写入内容超过 8 MiB 时拒绝受保护编辑；Bash 的授权与未覆盖边界保持独立。

外部改动会形成持久边界。例如 Agent 把 A 改成 B，用户把 B 改成 U，Agent 再把 U 改成 C：新增的 `external baseline` 检查点可以把 C 恢复为 U，跨越这条边界回到 A 会被拒绝。重新读文件、回退对话或手动凑回旧哈希不会消除边界；其他会话的编辑也不能被当前会话悄悄撤销。

回退后的旧分支检查点及其副本继续保留。`/rewind inspect <checkpoint_id>` 只读列出保留版本、校验和与内容副本位置，便于人工查阅或合并。已离开分支的检查点不会被当成当前编辑链的自动恢复目标。

## 文件恢复中再次退出

多文件恢复不是原子事务。程序先预检整个集合，保存回退前副本和恢复计划，再逐个原子替换/删除文件并记录进度。检测到冲突就停止，不提供跳过核查的强制覆盖开关。

重新启动后，`/recover` 会列出未完成的恢复及其所属会话。恢复该会话后：

```text
/rewind resume <restore_id>
/rewind resume <restore_id> apply
```

第一条只展示每个文件是“尚未恢复”“已经达到目标”还是“冲突”；第二条明确确认继续剩余步骤。已经达到目标的文件不再重复写入。文件完成后才提交对话边界，该边界按恢复 ID 幂等保存；不会自动反向回滚，也不会把部分完成显示为整体成功。

回退前副本始终保留在内容对象中，`/rewind resume <restore_id>` 也显示这些副本的位置。第一版没有一键撤销已完成回退或自动合并冲突的界面；可先保留当前用户修改，再从只读展示的副本人工取回需要的内容。遇到冲突需要先保留/转移用户修改，再重新查看恢复计划。

## 数据保留与清理

执行和检查点元数据默认位于 `~/.nanocursor/recovery/`，内容对象、锁也在此目录；`NANOCURSOR_HOME` 可更换应用目录。会话 JSONL 继续位于项目状态目录，恢复记录关联其来源。删除 Worktree 不会同时删除用户目录中的唯一恢复资料。

这些本地记录可能含工具参数、文件正文和旧内容，以私有文件权限保存；不是加密保险库。不要公开上传恢复目录。它也不是异机备份，整块磁盘或恢复目录丢失无法靠本机制恢复。

```text
/rewind storage
/rewind pin <checkpoint_id>
/rewind unpin <checkpoint_id>
/rewind cleanup
```

100 个检查点是软上限：只会自动剪除超过上限且无引用的空检查点。固定点、文件编辑链、恢复记录和活动运行引用继续保留；`cleanup` 也只删除无引用的检查点，不删除文件版本或恢复证据。普通会话清理不会删除仍有这些引用的会话。复杂配额及历史文件版本的批量回收尚未提供，因此有编辑证据的历史可能超过上限。

旧版没有索引的磁盘备份不会自动猜测归属或导入恢复列表。旧会话仍可查看，新的运行建立新执行记录；不能为旧操作补造执行保证。恢复数据库不支持被旧版本程序静默覆盖。

## 可选 Worktree

默认在当前项目编辑。大改动可以显式新建 Worktree：

```bash
nanocursor --worktree refactor
```

它从 Git 提交建立新分支，不包含原目录未提交的修改。若源目录有未提交或未跟踪内容，交互启动会要求确认；非交互调用须显式接受从提交开始：

```bash
nanocursor --worktree refactor --worktree-from-commit -p '阅读项目结构'
```

界面内可用：

```text
/worktree create refactor
/worktree create refactor HEAD --from-commit
/worktree list
/worktree status
/worktree exit
```

不会偷偷 stash、commit、复制 dirty 内容或改动原 index。名称冲突、Git 查询失败、创建/移除失败时保留可核查成果；重启后使用已保存的创建基线，不把新 HEAD 当原始基线。

默认不共享 `node_modules`、`.venv` 或 `vendor`，也不自动复制 `.env`。依赖按需独立安装；要复制指定 ignored 文件，可在项目 `.worktreeinclude` 中写显式允许的相对路径或模式。若在 `worktree.symlink_directories` 明确配置共享目录，这些目录仍会写穿到原项目，界面会显示共享范围。

退出、取消、失败默认保留目录和分支。任务完成后自行审阅 diff、测试、提交并合入，不自动 merge/cherry-pick。确需移除时：

```text
/worktree exit --remove
/worktree exit --remove --confirm <展示的确认_token>
```

确认绑定当前目录、分支和内容，内容变更后失效；模型自行填写 `discard_changes=true` 不是用户授权。活动任务、未知操作或未完成恢复会阻止删除。删除失败会保留登记和必要分支，不报告整体成功。

Worktree 只隔离普通 checkout 文件；共享 Git refs/config、绝对路径写入和外部服务仍依赖权限与沙箱。已有 OS Bash 沙箱保持可选，未因检查点而自动关闭或放宽。

## 当前限制

历史浏览器入口 `--remote` 已停止执行，避免绕过恢复保护。客户端断线重连、SSE/WebSocket 事件补发及远程审批恢复仍未发布。

恢复保证针对本地文件系统和遵守协议的 nanoCursor 进程；不提供任意 Bash/MCP 恰好执行一次、外部服务自动回滚、全部后台后代进程识别或强制断电的跨硬件保证。进程强杀与磁盘故障注入测试不等同于真实断电测试，外部编辑器也不参与文件锁。原生 Windows 的执行锁、目录同步和沙箱适配仍需独立开发与验收。
