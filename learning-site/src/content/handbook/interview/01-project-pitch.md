# 面试讲述模板：nanoCursor

最后更新：2026-06-06

## 1. 30 秒版本

nanoCursor 是我做的一个本地 AI 编程工作台，核心不是简单聊天，而是围绕代码任务实现了一套轻量 Agent Runtime。用户在前端提交需求后，后端 Lead Agent 会先判断任务复杂度，简单问题直接回答，复杂任务再按需创建 Planner、Coder、Reviewer、Tester 等临时 Agent，并结合项目索引、上下文压缩、工具权限和 SSE 事件流完成可观测的代码修改流程。

## 2. 1 分钟版本

nanoCursor 是一个前后端分离的 AI 编程工作台。前端类似轻量 Codex 工作台，负责会话、工作区、Agent 动态、进度和 Diff 展示；后端基于 FastAPI 实现运行入口、EventStore、Agent Loop、上下文管理、工具治理、MCP/Skills 和恢复机制。

我比较关注两个问题：第一，Agent 不能每次都走固定流程，所以我做了意图路由和 Lead 直接回答机制，简单问答不会创建完整任务流；第二，Agent 真正能干活必须有上下文和工具边界，所以项目里实现了项目索引、会话摘要、工具权限分级、审批、路径安全和快照恢复。整体目标是把一个 AI 编程工具的核心机制拆开实现，而不是只做一个聊天 UI。

## 3. 3 分钟版本

这个项目最初是一个基于多 Agent 的编程助手，后来我逐渐发现固定 DAG 和 LangGraph 风格不太适合交互式编程任务，所以后面重构成了更接近 Agent Loop 的结构。

现在的主链路是：用户在前端会话里提交需求，后端根据 conversation_id 和 workspace_dir 找到当前上下文，然后由 intent router 判断这是问候、解释、只读分析、代码修改、debug 还是高风险操作。如果是简单问题，Lead 直接回答；如果是代码任务，系统会组合本轮 runtime team，生成 execution plan、工具策略和验收标准，然后注册 RunContext，创建 EventStore session，启动后台 Agent Loop。

运行过程中，Agent 会根据上下文调用受控工具，比如读文件、写文件、运行测试、召回记忆、调用 MCP 或 Skills。每个阶段、工具调用、Agent 活动、错误和交付物都会写入事件流。前端通过 SSE 消费事件，把当前 Agent 正在做什么、右侧进度、Diff、恢复点和交付物展示出来。

我觉得这个项目最核心的难点不是“有几个 Agent”，而是让 Agent 在本地项目里可控地工作：要知道什么时候少做，什么时候分工；知道该看哪些上下文；知道哪些工具可以用，哪些需要审批；还要让用户能看到系统不是卡住了。

## 4. 简历版三条

- 设计轻量 Agent Runtime：基于 FastAPI 构建会话级 run 入口和 Agent Loop，Lead Agent 根据用户意图决定直接回答、只读分析或进入代码交付流程，并按需创建临时 Planner/Coder/Reviewer/Tester，实现“少即是多”的动态协作。
- 构建上下文与记忆机制：实现项目索引、文件 outline、会话摘要、运行摘要、用户偏好和 Skills 注入，根据任务选择相关文件和历史信息，避免将完整项目和完整聊天历史无差别塞入模型上下文。
- 实现工具治理与可观测运行：设计工具权限分级、路径安全、审批、备份和恢复机制；基于 EventStore + SSE 持久化并实时推送 Agent 活动、阶段状态、工具调用、Diff、错误和交付证据，提升自动化代码修改的可控性和可复盘性。

## 5. 容易被追问的问题

### Q1：为什么不用 LangGraph？

早期确实用过类似固定流程的思路，但交互式编程任务经常需要根据中间结果动态调整下一步。固定 DAG 容易让系统变成“流程图驱动”，而不是“状态观察后自主决策”。所以我后来把核心改成 Lead 驱动的 Agent Loop，只保留 execution plan 作为边界和验收约束，而不是把它当成固定 DAG。

### Q2：多 Agent 是否真的有必要？

不是所有任务都需要多 Agent。项目现在默认只有 Lead，简单问答直接回答；只有当任务需要计划、代码实现、测试复核或安全审查时才创建临时子 Agent。我的重点不是堆 Agent，而是让系统知道什么时候不该创建 Agent。

### Q3：项目最工程化的地方是什么？

我认为是三块：会话级 run 和 EventStore，让任务过程可恢复；上下文和记忆选择，让模型输入可控；工具权限和审批，让 Agent 修改代码时有边界。

### Q4：当前最大短板是什么？

前端体验还有一些细节问题，后端也还需要继续强化异步边界、类型模型和安全策略。它目前更适合单机本地工作台和学习型工程项目，还不是多用户生产 SaaS。
